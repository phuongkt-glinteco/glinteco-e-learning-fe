# Frontend Internationalization (i18n) Standards

Tài liệu này quy định tiêu chuẩn đa ngôn ngữ trong dự án Frontend sử dụng thư viện **`next-intl`**.

---

## 1. Nguyên tắc "Zero Hardcoded Strings"

- **Nghiêm cấm** viết trực tiếp chuỗi văn bản hiển thị cho người dùng (Tiếng Việt hoặc Tiếng Anh) trong mã nguồn JSX/TSX.
- Mọi văn bản hiển thị trên UI (nhãn nút bấm, tiêu đề, mô tả, thông báo lỗi, placeholder) **bắt buộc** phải sử dụng hàm dịch của `next-intl`.

### Trong Client Components (`'use client'`)
```tsx
import { useTranslations } from 'next-intl';

export function LessonHeader() {
  const t = useTranslations('LessonEditor');
  return <h1>{t('title')}</h1>;
}
```

### Trong Server Components / Server Actions
```tsx
import { getTranslations } from 'next-intl/server';

export async function PageHeader() {
  const t = await getTranslations('LessonEditor');
  return <h1>{t('title')}</h1>;
}
```

---

## 2. Quy tắc Đồng bộ Song ngữ (`vi.json` & `en.json`)

- Các file bản dịch chính được lưu tại:
  - `fe/messages/vi.json` (Tiếng Việt)
  - `fe/messages/en.json` (Tiếng Anh)
- **Quy tắc bắt buộc:** Bất kỳ khi nào thêm mới, sửa đổi hoặc xóa một translation key, lập trình viên/agent **phải cập nhật đồng thời cả hai file `vi.json` và `en.json`**.
- Không để xảy ra tình trạng có key ở tiếng Việt nhưng thiếu ở tiếng Anh (hoặc ngược lại).

---

## 3. Quy chuẩn Đặt tên Key & Namespace

- Sử dụng **cấu trúc phân cấp namespace** theo tính năng hoặc màn hình thay vì danh sách phẳng:
  - `Common.*`: Các từ/cụm từ chung toàn app (`save`, `cancel`, `delete`, `edit`, `loading`).
  - `LessonEditor.*`: Các chuỗi thuộc riêng màn hình chỉnh sửa bài học.
  - `ApiErrors.*`: Các chuỗi thông báo lỗi trả về từ API theo mã code.
- Tên key viết theo chuẩn `camelCase`:
  ```json
  {
    "LessonEditor": {
      "saveDraft": "Lưu bản nháp",
      "publishSuccess": "Xuất bản bài học thành công"
    }
  }
  ```
